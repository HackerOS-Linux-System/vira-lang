Instalacja i pierwszy plik

hyperc to pojedyncza binarka Go, bez zależności runtime poza samym Node.js do uruchamiania wygenerowanego JS.

go build -o hyperc ./src/hyperc
go build -o hyperfmt ./src/hyperfmt
go build -o hyperls ./src/hyperls
// hello.hyper
fn greet(name: string = "World") -> string => `Hello, ${name}!`

fn main() {
    console.log(greet())
    console.log(greet("Hyper"))
}

main()
$ hyperc hello.hyper -o hello.js
$ node hello.js
Hello, World!
Hello, Hyper!
Na co dzień lepiej używać vira run zamiast ręcznego hyperc + node - patrz dokumentacja vira.

hyperc

hyperc robi wyłącznie kompilację. Żadnych podkomend build/run/fmt/lsp - te żyją w vira, dokładnie jak gofmt/gopls są osobnymi binarkami od go.

FlagaZnaczenie
-o <plik>zapisz JS do pliku zamiast na stdout
--checktylko parsuj i sprawdź typy, nic nie emituj
--jsondiagnostyki jako JSON (do narzędzi, np. vira/LSP)

Typy i zmienne

Domyślnie niemutowalne, jak w Rust - let mut włącza mutowalność. Typy prymitywne: i8..i64, u8..u64, f32, f64, string, bool, any, void.

let name: string = "Hyper"     // niemutowalna
let mut counter: i32 = 0        // mutowalna
counter = counter + 1

const VERSION = "0.1.0"         // zawsze niemutowalna

Adnotacje typów są dziś weryfikowane dla literałów i prostych łańcuchów wywołań, ale nie ma jeszcze pełnej unifikacji typów (patrz Stan implementacji).

Funkcje

fn add(a: i32, b: i32) -> i32 {
    return a + b
}

// forma wyrażeniowa
fn double(x: i32) -> i32 => x * 2

// parametry domyślne, async/await
async fn fetchJson(url: string) -> any {
    let res = await fetch(url)
    return await res.json()
}

struct i impl

Kompiluje się do zwykłej klasy JS. Metody w impl dopisywane są do prototypu.

struct Point {
    x: f64,
    y: f64,
}

impl Point {
    fn length(self) -> f64 {
        return Math.sqrt(self.x * self.x + self.y * self.y)
    }
}

let p = Point { x: 3.0, y: 4.0 }
console.log(p.length())
Wewnątrz metod self jest statycznie rozpoznawane i tłumaczone na this - również wewnątrz template literali.

enum i match

Algebraiczne typy danych (ADT) kompilowane do klasy z tagiem + statycznymi fabrykami wariantów. match kompiluje się do IIFE z destrukturyzacją pól.

enum Shape {
    Circle(radius: f64),
    Rectangle(width: f64, height: f64),
}

fn area(shape: Shape) -> f64 {
    return match shape {
        Circle(r) => 3.14159 * r * r,
        Rectangle(w, h) => w * h,
    }
}
Checker ostrzega (nie blokuje kompilacji), jeśli match nad znanym enumem nie jest wyczerpujący - dodaj brakujące warianty albo klauzulę _.

trait

Kontrakt strukturalny egzekwowany przez checker: impl Trait for X musi zaimplementować każdą metodę zadeklarowaną w trait, inaczej kompilacja się nie powiedzie.

trait Reporter {
    fn info(self, msg: string) -> void
    fn error(self, msg: string) -> void
}

struct ConsoleReporter { prefix: string }

impl Reporter for ConsoleReporter {
    fn info(self, msg: string) -> void {
        console.log(`${self.prefix} ${msg}`)
    }
    fn error(self, msg: string) -> void {
        console.error(`${self.prefix} ✗ ${msg}`)
    }
}

Obsługa błędów

fn withdraw(balance: f64, amount: f64) -> f64 {
    if amount > balance {
        throw new Error(`za mało środków`)
    }
    return balance - amount
}

try {
    withdraw(100.0, 1000.0)
} catch (e) {
    console.log(`złapano: ${e.message}`)
} finally {
    console.log("gotowe")
}

Generyki

Generyki są parsowane i (celowo, jak w tsc) usuwane w czasie transpilacji - JS jest dynamicznie typowany, więc runtime i tak by ich nie użył. hyperc emituje za to JSDoc (@template/@param/@returns), dzięki czemu edytor nadal podpowiada typy w wygenerowanym pliku.

fn firstOrDefault<T>(items: T[], fallback: T) -> T {
    if items.length > 0 { return items[0] }
    return fallback
}

Interoperacyjność z JS

Rdzeń obietnicy Hyper Lang: import trafia 1:1 do ESM, bez pisania ani utrzymywania osobnych plików .d.ts.

import { readFileSync } from "fs"
import path from "path"
import { load as parseYaml } from "js-yaml"  // alias przez `as`

let data = parseYaml(readFileSync("config.yml", "utf8"))

Słowa kluczowe są legalnymi nazwami właściwości po . (jak w JS) - promise.catch(...) działa mimo że catch jest zarezerwowanym słowem gdzie indziej.

Moduły i pub

Lokalne importy (./ lub ../) są rozwiązywane przez bundler i scalane w jedną przestrzeń nazw. Deklaracje bez pub są prywatne dla pliku, w którym powstały - checker to egzekwuje.

// geometry.hyper
pub struct Rectangle { width: f64, height: f64 }
fn internalHelper() -> string { ... }   // prywatne

// main.hyper
import { Rectangle } from "./geometry.hyper"
import { internalHelper } from "./geometry.hyper"  // błąd kompilatora
Cykle importów i kolizje nazw między plikami są wykrywane jako błędy kompilatora przed wygenerowaniem JS, nie jako runtime crash.

Checker i diagnostyka

Diagnostyki niosą numer linii, kolumnę i ścieżkę pliku źródłowego (nawet gdy błąd jest w zaimportowanym module, nie w pliku wejściowym).

$ hyperc main.hyper
math_utils.hyper:error:8:16: niezdefiniowany identyfikator `sqrt`
  8 |         return sqrt(self.x * self.x)
                     ^
hyperc: kompilacja przerwana - błędy w main.hyper

Sprawdzane dziś: arność wywołań (w tym metod), niemutowalność, istnienie pól/metod na znanych strukturach, zgodność traitów, wyczerpujący match, widoczność pub, podstawowa zgodność typów prymitywnych w przypisaniach i łańcuchach wywołań.

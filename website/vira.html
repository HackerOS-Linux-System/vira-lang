vira

Menedżer pakietów i budowania Hyper Lang, napisany w samym Hyper Lang (vira/src/*.hyper, skompilowane przez hyperc). Inspirowany Cargo: jeden manifest, jeden lockfile, natywna obsługa pakietów bez osobnego rejestru typów.

Brak wyników.

Podstawy

vira.yml Workspace

Komendy

vira new vira install / remove vira search vira check vira fmt vira build vira run vira lsp vira publish

Rejestry

npm / JSR / vira.io

vira.yml

Manifest w YAML (nie TOML jak Cargo.toml - świadomy wybór, YAML jest wszechobecny w ekosystemie JS/npm).

package:
  name: moj-projekt
  version: 0.1.0
  license: MIT

# Hyper Lang jest przed 1.0 i nie ma "edycji" jak Rust - zamiast tego,
# jak `go 1.22` w go.mod, wskazujemy minimalną wersję hyperc.
hyperc:
  version: "0.0.1"

dependencies:
  left-pad: "^1.3.0"
  jsr:@luca/cases: "^1.0.0"

dev-dependencies: {}

Workspace

Wiele pakietów w jednym repo, każdy z własnym vira.yml - dokładnie jak Cargo workspace.

# vira.yml w katalogu głównym
workspace:
  members:
    - vira
    - inny-pakiet

vira new

$ vira new moj-projekt
vira: utworzono nowy projekt w ./moj-projekt

Tworzy vira.yml i src/main.hyper ze wzorcowym "Hello World".

vira install / vira remove

$ vira install                    # instaluje wszystkie zależności z vira.yml
$ vira install left-pad           # dopisuje i instaluje jedną (npm)
$ vira install jsr:@luca/cases    # z JSR
$ vira install vira:nidus         # z rejestru społecznościowego vira.io
$ vira remove left-pad

Każdy install honoruje zakres semver z vira.yml (^, ~, dokładna wersja, *), zapisuje rozwiązane wersje w vira.lock i realnie pobiera + rozpakowuje paczkę do .vira/packages/<nazwa>@<wersja>/ (tarball dla npm/JSR, płytki git clone dla vira.io).

Płaska struktura .vira/packages/ - bez zagnieżdżonych zależności przechodnich. Rozwiązywanie całego drzewa zależności to kolejny krok.

vira search

$ vira search chalk
chalk@5.6.2 - Terminal string styling done right
...
$ vira search cases --registry jsr

vira check

Parsuje i sprawdza typy całego projektu (podążając za wszystkimi lokalnymi importami) bez emitowania JS - szybka pętla informacji zwrotnej, odpowiednik cargo check / tsc --noEmit.

$ vira check
src/main.hyper: OK

vira fmt

$ vira fmt              # formatuje wszystkie pliki .hyper w src/
$ vira fmt --check      # tylko sprawdza (exit 1 jeśli niesformatowane)

Pod maską woła hyperfmt - osobną binarkę, jak gofmt.

vira build

$ vira build              # transpiluje do dist/<nazwa>.js
$ vira build --release    # buduje samodzielną binarkę

--release wykrywa cel automatycznie (albo wymuś przez --target tauri):

WykrytoStrategia
src-tauri/ istnieje, albo --target taurigeneruje minimalny szkielet Tauri jeśli brak (Cargo.toml, tauri.conf.json, main.rs), potem deleguje do npx tauri build
w przeciwnym razieNode.js Single Executable Application (node --experimental-sea-config + postject)
Zbudowana binarka SEA to realny, samodzielny plik wykonywalny (kopia binarki Node z wstrzykniętym bundlem) - nie wymaga zainstalowanego Node.js na maszynie docelowej. Nie jest to jednak cross-kompilacja: binarka powstaje dla platformy, na której działa vira build --release.
Szkielet Tauri jest generowany i sprawdzony (poprawne pliki), ale samo cargo tauri build wymaga toolchainu Rust/Tauri CLI na Twojej maszynie - nie zostało uruchomione w środowisku, w którym to powstało.

vira run

$ vira run              # kompiluje do pliku tymczasowego i uruchamia przez node
$ vira run --release    # uruchamia wcześniej zbudowaną binarkę bezpośrednio

vira lsp

Uruchamia hyperls (serwer LSP) i przezroczyście przekazuje mu stdio - do skonfigurowania jako language server w edytorze.

Funkcja LSPStatus
Diagnostyka na żywo (parser + checker)gotowe
Formatowanie dokumentugotowe
Hover + go-to-definition (deklaracje top-level)gotowe
Completion (świadomość zasięgów lokalnych)nie zaczęte

vira publish

$ vira publish                       # publikuje do npm
$ vira publish --registry jsr        # publikuje do JSR
$ vira publish --registry all        # oba

Generuje package.json/jsr.json z vira.yml i deleguje do npm publish / npx jsr publish. Uwierzytelnienie (npm login, token JSR) to odpowiedzialność użytkownika - vira tego nie robi za niego.

npm / JSR / vira.io

PrefiksRejestrStatus
braknpm (registry.npmjs.org)przetestowane realnie
jsr:JSR przez warstwę kompatybilności npm.jsr.ionapisane analogicznie do npm, nieprzetestowane w tym środowisku
vira:vira.io - jeden plik JSON z listą repozytoriów gitprzetestowane realnie

Indeks vira.io to pojedynczy plik utrzymywany na GitHubie:

https://github.com/vira-io/repository/blob/main/repo-list.json
{
  "libraries": [
    { "nidus": "przykladowe-repo.git" }
  ]
}
Pakiety z vira.io to dziś surowe repozytoria git bez wersjonowania semver - "wersja" to zawsze najnowszy stan gałęzi domyślnej (oznaczana jako git w vira.lock).
